# 设计决策

## 核心信息少，默认值明确

用户提供主机、账号、认证信息和授权目录，Agent 即可生成配置并注册 MCP。端口、只读权限、字节上限、并发和超时有默认值。高级选项可省略，错误值和未知字段仍明确拒绝，不用默认值掩盖错误。

## 一种 YAML 模型覆盖多服务器

沿用 `servers → connection / mounts`，每个挂载有独立权限和稳定 ID。单台服务器也使用同一结构，扩展时无需切换到另一套 DSN、JSON 或逐字段 CLI 模型。配置修改通过重启生效。

## 允许本机直接密码，环境变量可选

强制环境变量会把简单连接拆成多个配置步骤，并引入桌面进程继承、Windows 语法和变量生命周期问题。本地私有 YAML 因此允许直接填写密码，环境变量适合已有凭据注入流程；两者互斥，不隐式覆盖。

两种方式都不是加密或隔离。真实配置放在仓库外并限制权限，用户可以自行补填密码，不必把密码交给聊天。私钥只通过本机路径引用。当前不引入独立凭据库或交互式向导。

## 权限由用户选择，操作保持封装

一台服务器可授权多个目录，目录范围覆盖全部子目录和普通文件。除直接挂载 `/` 外，不按目录名称设置黑名单，`/root` 与其他规范路径同等处理。服务器账号的 OS 权限仍必须允许相关操作。

对用户只提供 read、write、delete 三类权限，默认 read。read 包含列目录、属性、读取、tail、搜索和归档读取；write 包含创建、覆盖/追加、目录创建、重命名/移动和解压目标写入；delete 单独控制文件与目录删除，write 不隐含 delete。跨挂载移动检查两端 write，解压检查源 read 和目标 write。父目录授权涵盖其子树，另一个更窄的挂载不能撤销已由父目录授予的权限。

SSH 仅承载 SFTP。文件创建、覆盖/追加、目录创建、移动、删除和归档解压均为封装动作，不接受自定义 Shell 命令或任意主机。归档在本地解析后通过受控 SFTP 写回，归档中的路径、链接和类型必须经过校验。

## 资源预算服务于实际开销

响应大小、总扫描量、读写量、递归/归档条目、展开字节、超时与并发保留可解释的上限。搜索扫描预算独立于读取响应预算，不能因 read_file 每次只返回几 MiB 就只搜索大型日志的开头。移除小型服务器/挂载数量和路径层数限制，目录和递归预算采用更符合常规文件系统使用的默认值。

## SSH 兼容范围采用白名单

ssh2 并不自动继承 OpenSSH 的所有行为。只解析能验证的基础字段，不调用 `ssh -G`；OpenSSH 的 Match exec 具有本地命令执行语义，固定 argv 不能使配置求值自动变成无副作用操作。

复杂配置明确拒绝，允许用户改用显式连接与认证。原生 SSH 免登录也不能证明 Agent 已加载身份，两者的来源必须区分。[OpenSSH 配置语义](https://man.openbsd.org/ssh_config.5)

## 便利性不改变安全边界

主机密钥不能自动信任，授权目录没有隐式默认值。所有已有路径段中的链接都拒绝，包括指向挂载内的链接，以保持策略一致。

客户端检查无法消除 TOCTOU，也不能阻止同一 Agent 使用其他 SSH 入口。服务器级隔离由受限账户、OS 权限和 SFTP chroot 提供，不以“默认只读”替代这些保障。
